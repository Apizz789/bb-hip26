# Architecture — BBL HI PRO (React + TypeScript, mock / demo)

Scope: this describes the code as it exists in this repository. It is a mock/demo application. It has no
backend, no authentication, no Bangkok Bank integration, and no real customer data. See README.md for the
overview and MIGRATION_STATUS.md for verified results and limitations.

## 1. Folder structure

## 2. Pages and routing
Hash router in `src/app/router.ts`. Routes:

| Hash | Page (feature folder) |
|---|---|
| `#home` | home (HomePage) |
| `#services` | services hub (ServicesPage) |
| `#svc-documents` | document request (document-request) |
| `#svc-appointment` | appointment booking (appointments) |
| `#svc-tracking` | request tracking (tracking) |
| `#svc-overview` | financial overview (OverviewPage) |
| `#wellness` | Financial Wellness (wellness) |
| `#goals` | Financial Goals (goals) |
| `#playground` | Playground — the 3D zoo in an iframe (`public/zoo/index.html`, locked at v10.13) |
| `#contact` | contact (contact) |
| `#brand` | brand page (brand) |

- An unknown hash renders the home page but **keeps the unknown hash in the URL**. This is a known behaviour
  difference (see MIGRATION_STATUS.md).
- `SKELETON_ROUTES` (`home`, `goals`, `wellness`, `svc-overview`, `svc-tracking`) show a loading skeleton
  before the page content appears.
- `useRoute()` returns `{ route, navId }`. `navId` increments only when the route really changes. Loading is derived
  synchronously from it: `loading = skeleton route && doneNav !== navId`. A timer (420 ms, 150 ms when reduced motion
  is set) only records completion in `useRouteLoading`.
- `useRouteFocus(navId, loading, mainRef)` focuses `.view.active h1` once per `navId`, when loading has finished. The
  first load is skipped. The h1 has `tabIndex=-1`. Focus already inside the active view (not on the heading) is left alone.
- The skip link (`components/layout/Shell.tsx`) targets the active view's h1 only when the view is not loading. Otherwise
  it targets `#app` (the `<main>`, `tabIndex=-1`).
- There is no router library. Navigation is `location.hash` plus a `hashchange` listener.

## 3. State
Three providers, composed in `providers.tsx`:

- **LanguageProvider** — current language (`th` default, or `en`). The only persisted value: `localStorage`
  key `bblhipro-lang`, read and written through `utils/storage.ts` inside try/catch. The app works if storage
  is unavailable.
- **StoreProvider** — one `useReducer` over the pure reducer in `src/store/appState.ts`. Holds goals, document
  requests, appointments, contact submissions, and simulated savings. **In memory only.** Everything resets on
  reload.
- **FeedbackProvider** — toast queue, auto-dismiss after 2600 ms.

Business rules live in `src/domain/*` as pure functions and are unit-tested. Components call domain functions;
they do not hold the rules themselves.

## 4. View wrapper (`components/layout/View.tsx`)
All pages stay mounted. Visibility is controlled by `ViewStateContext` (active page, loading flag). Keeping pages
mounted preserves form input across navigation. While a skeleton route is
loading, `SkeletonFor` renders inside the active view.

## 5. Localisation
- `src/i18n/dictionary.ts` is **generated** from the prototype's `const S` object by
  `scripts/generate-dictionary.mjs`. It holds 339 keys as `[Thai, English]` tuples and exports a `TranslationKey`
  type.
- Run `npm run generate:i18n` to regenerate. It reads `../preview_p4.html`. Do not hand-edit the file. The
  generator was pointed at the older `preview.html` (264 keys) before this handoff; that was corrected.
- `translate.ts` provides `createTranslator` and `missingKeys()` (lists keys referenced in code but absent from
  the dictionary).
- `lastSimulated: { id, seq }` records the last goal that received a simulated save. `seq` increases on every save.
  The goal card and home card use it through `useGoalBump` to replay the highlight.
- Some typed lookup maps (`GREET_KEY`, `NOTIF_KEYS`, status maps in domain files) use `Record<…, TranslationKey>`
  so a missing key is a compile error where type-checking runs.

## 6. Mock data and persistence
- All data is fictional. `src/data/mock.ts` holds the seed values. Each page that shows mock data is labelled as
  mock/demo in the UI. Contact and Playground do **not** show a mock tag (known gap).
- Simulated actions (document request submit, appointment confirmation, goal savings, contact form) update the
  in-memory store and show feedback. They do not call any service.
- Persistence: only `bblhipro-lang`. Do not add persistence for financial data. A new persistence layer would need
  its own review.

## 7. Styling
- `tokens.css` defines design tokens on `:root`, copied from the prototype.
- `components.css` is the prototype stylesheet, copied from the prototype. It is global and unscoped, so class names
  collide across the app. Changing it changes visual regression output.
- One deliberate difference: the goal highlight rule is scoped under `.view.active` so it beats `.view.active .reveal`.
  The prototype has the same conflict, so its highlight never played visibly. See MIGRATION_STATUS.md §3.
- The `h3-look` class (in components.css) gives an `<h2>` the visual style of an `<h3>`. It was used where the
  prototype had `<h3>` directly under `<h1>`, to keep heading order valid.
- The `container` class is on `<main>` in App.tsx. It is required for the layout gutter; missing it caused a visual
  regression that was fixed.

## 8. Build and dev
- **Build** (`npm run build`): esbuild bundles `src/main.tsx` to `dist/app.js` (IIFE, minified,
  `process.env.NODE_ENV="production"`, target es2022). It writes `dist/index.html` and copies `public/`. A rebuild from
  unchanged source is byte-identical.
- **Dev** (`npm run dev`): esbuild watch and servers on http://localhost:5173. It writes only to `.dev/`
  (index.html, app.js with sourcemaps, app.css, and public/). It never writes `dist/`. The first version wrote to
  `dist/` and was fixed.
- **Typecheck** (`npm run typecheck`): `tsc -p tsconfig.json`, strict settings (`noUnusedLocals`,
  `noUnusedParameters`, `noImplicitOverride`, `isolatedModules`, `skipLibCheck`, `jsx: react-jsx`). It passes on macOS, with the type packages installed (§9).

## 9. Testing
| Layer | Tool | Command | Status |
|---|---|---|---|
| Unit (domain, store) | node:test + tsx | `npm run test:unit` | 21 / 21 pass |
| E2E | Playwright (.cjs) against `dist/index.html` | `npm run test:e2e` | 12 / 12 suites pass, 243 checks |
| Visual | Playwright screenshots + Pillow pixel diff | `npm run test:visual` | worst 0.05% diff, threshold 24/255; heights identical in 30/30 pairs |
| Types | tsc | `npm run typecheck` | passes on macOS, with React, react-dom and Node types installed (see MIGRATION_STATUS.md §5) |

- **Shared runner** (`tests/e2e/helpers.cjs`): `runSuite` runs every check even after a failure, names the step that
  failed (with up to four error lines), and sets a non-zero exit code if any check fails. `waitState` waits for a named UI
  state and throws `timed out waiting for: <label>`. `becomes` resolves to true/false for a check. `routeReady`, `goRoute`
  and `splashGone` wait for the route, skeleton and splash states.
- **Suites** run by `run-all.mjs`: p1 (31), p2 (19), p3 (20), p4 (16), route-focus (17), features (52), features-more (28),
  journeys (13), interactions (16), a11y-dom (5), a11y-behaviour (13), responsive (13). Total 243.
- No fixed waits remain. Every suite waits for UI state. See MIGRATION_STATUS.md §4.
- **Visual** compares the prototype (`../preview_p4.html` by default, overridable with `PROTO_FILE`) with the React build
  at 390/430/768/1000/1440 px for home, services, wellness, goals, contact, and playground, with reduced motion and DPR 1.
  Animation timing is not compared.

## 10. Known architectural gaps
- Timers (toast, focus delay, reveal stagger) are not cleared on unmount. Not reachable today because pages stay mounted.
- Scroll-to-top on skeleton routes now runs when the page settles, not at the start of the navigation (MIGRATION_STATUS.md §5).
- Hash router keeps unknown hashes in the URL and has no 404 page.
- Accessibility: DOM and behaviour checks only (contrast, keyboard, dialog, reduced motion). No audit or WCAG claim (MIGRATION_STATUS.md §6).

## 11. Toolchain substitutions and future migration path
The intended stack was Vite + React Router + Vitest + React Testing Library + TypeScript with full
`@types/react` / `@types/node`. None of these could be installed (the npm registry was unreachable). This
project uses the substitutes listed below. **Vite, React Router, Vitest and Testing Library are not installed in this repository. The type packages are.**

| Intended | Currently used | Why |
|---|---|---|
| Vite | esbuild (scripts/build.mjs, scripts/dev.mjs) | registry unavailable |
| React Router | `src/app/router.ts` (hash router) | registry unavailable |
| Vitest | node:test via tsx | registry unavailable |
| React Testing Library | not used | registry unavailable |
| @types/react, @types/react-dom, @types/node | installed as devDependencies (macOS) | JSX, React DOM and Node types are checked by `typecheck` |

Future migration path, once the registry is reachable:
1. Done: `@types/react`, `@types/react-dom` and `@types/node` are devDependencies.
2. Done: `npm run typecheck` passes on macOS. Keep strict settings when changing code.
3. Decide whether to move to Vite; if so, port build.mjs / dev.mjs and index.html.
4. Decide whether to replace the hash router with React Router; keep the same route table and skeleton behaviour.
5. Decide whether to move unit tests to Vitest and add Testing Library; keep the domain tests as the baseline.
6. Re-run build, unit, E2E, and visual, and compare against the results recorded in MIGRATION_STATUS.md.
